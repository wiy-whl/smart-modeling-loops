## 1. 背景与目标

### 1.1 现有建模流程回顾

传统可视化建模通常遵循"建模四步法"，每一步都存在明显的效率瓶颈：

| 步骤 | 流程说明 | 主要局限 |
|------|----------|----------|
| **找数据** | 分析师需在多个系统中查找可用数据源 | 存在重复确认、权限障碍等问题，平均耗时占全流程 30% 以上 |
| **拖算子** | 手动从算子库中拖拽节点并连接 | 中等复杂度模型通常包含 50+ 个算子，操作繁琐、易出错且难以复用 |
| **配参数** | 依据业务需求配置各算子参数 | 无统一标准，高度依赖资深分析师经验，新人上手周期长达数周至数月 |
| **调结果** | 反复调整画布节点以验证可读性 | 影响协作沟通效率，尤其在团队评审场景下问题突出 |

### 1.2 用户痛点分析

在建模实践中，用户普遍面临三大核心挑战：

**痛点一：效率瓶颈——流程冗长低效**

手动操作占比过高，大量时间消耗在重复性配置工作上，导致建模周期拉长，难以满足敏捷业务需求。

**痛点二：学习成本——需求与现实脱节**

业务需求（"我想要……"）与建模实现（"该用哪个算子？"）之间存在显著的"翻译"成本，新手往往不知从何入手、该选用哪些组件。

**痛点三：经验依赖——知识难以沉淀**

复杂模型构建依赖个别专家，缺乏标准化流程与共享机制，模型成果难以复用和传承，组织知识资产无法有效积累。

### 1.3 AI 时代带来的交互范式改变

随着大语言模型技术的成熟，人机交互正在经历深刻变革：

> **交互趋势：由 GUI（图形用户界面）→ LUI（语言用户界面）**

用户不再需要通过复杂的菜单、拖拽和表单来完成任务，而是以自然语言直接表达意图，由 AI 理解并执行。这一范式转变，为数据建模领域带来了全新的可能性。

### 1.4 智能建模的目标

智能建模正是顺应这一趋势，致力于实现 **"所想即所建"** 的自然语言驱动建模新模式，具体目标包括：

| 目标维度 | 说明 |
|----------|------|
| **只需描述想法** | 用户以自然语言描述建模需求，智能建模自动规划并生成可运行的模型方案 |
| **思维直达结果** | 缩短从业务想法到模型落地的路径，让分析师专注于业务逻辑而非工具操作 |
| **实现知识复用** | 构建可积累、可传承的行业建模知识体系，避免重复造轮子 |
| **提升建模效率** | 将原本需要数小时的手动建模过程压缩至分钟级，显著提升整体工作效率 |
| **智能覆盖全流程** | 在建模全生命周期提供 AI 支持，覆盖规划、改写、续写、验证等各个环节 |

## 2. 总体架构

### 2.1 什么是智能建模

**智能建模**是一个以 **自然语言** 为交互界面，以 **行业知识库** 为大脑，由 **AI 智能体** 驱动的革命性功能。

它由三层架构协同工作：

```
┌─────────────────────────────────────────────────────────┐
│                      交互层                              │
│              自然语言对话框 · 您的指令                      │
├─────────────────────────────────────────────────────────┤
│                      智能层                              │
│        建模规划 Agent + 三大知识库（AI 大脑）              │
├─────────────────────────────────────────────────────────┤
│                      执行层                              │
│              实时联动的可视化画布 · 最终成果                │
└─────────────────────────────────────────────────────────┘
```

- **交互层**：用户通过自然语言对话框下达建模指令，无需手动拖拽和配置。
- **智能层**：建模规划 Agent 结合数据表、算子、模型三大知识库，进行深度分析与方案规划。
- **执行层**：AI 生成的建模方案实时渲染至可视化画布，用户可随时查看、编辑和验证。

### 2.2 七大核心能力

智能建模围绕以下七大核心能力构建，覆盖从意图输入到模型产出的完整链路：

| 能力 | 核心价值 |
|------|----------|
| **建模规划** | 输入自然语言后，自动生成完整算子流与执行逻辑，支持一键批准或分步确认 |
| **模型改写** | 支持用自然语言修改现有节点参数或结构调整，如"把这个分类模型换成 XGBoost" |
| **模型续写** | 在已有模型末尾自动延伸后续处理节点，保持业务逻辑连贯性与完整性 |
| **指令模板** | 无需从零编写指令，只需根据自身需求修改相关参数，即可实现快速建模 |
| **知识库** | 支持在对话中直接引用预置表、算子、模型模板，增强表达精确性与执行准确性 |
| **上下文引用** | 将数据、算子、画布元素便捷引用至对话上下文，实现精准度提升 |
| **快捷 AI 操作** | 建模画布中一键调用 AI 能力，包括智能重命名、智能注释、智能改写 |

## 3. 核心功能

### 3.1 建模规划——从"想法"到"模型"的自动驾驶

建模规划是智能建模的核心入口，实现全链路自动化建模规划。

**工作流程：**

1. **输入建模指令**：用户以自然语言描述建模所需的数据、具体业务场景、拟采用的构建方法等。
2. **深度分析与思考**：建模助手调用知识库，对需求进行深度分析，规划合理的建模方案。
3. **方案生成与执行**：自动生成数据表调用、算子配置、模型方案，并在画布上完成配置生成与渲染。
4. **结果验证**：全面检验建模结果，确保方案可运行、逻辑正确。
5. **支持重新规划**：若方案不满足预期，用户可发起重新规划，助手将基于反馈调整方案。

**典型场景示例：**

> 用户输入："基于近三个月的用户行为数据，构建一个流失预警模型，使用随机森林算法，输出高风险用户名单。"

建模助手将自动完成数据表选取、特征工程算子配置、模型训练节点搭建及结果输出节点的全流程规划。

### 3.2 模型改写——建模需求变更，一句话即刻生效

在建模规划或执行过程中，若需调整方案或节点配置，用户只需描述改写指令即可。

**核心特性：**

- 通过自然语言描述改写意图，如"将时间范围改为最近 6 个月"、"把聚合方式从求和改为平均值"。
- 建模助手接收改写指令后，**实时联动画布**，对相关配置进行更新。
- 确保最新配置**及时、准确**地在画布上呈现，无需手动查找和修改节点。

### 3.3 模型续写——灵活敏捷，让模型"活"起来

当模型构建到一半，或已有部分模型时，用户可指定一个算子节点，向建模助手描述续写指令。

**核心特性：**

- 用户**指定起始算子节点**，描述后续需要补充的处理逻辑。
- 建模助手理解当前指定节点的**基础和上下文**，自动完成模型的**补全工作**。
- 在已有模型末尾自动延伸后续处理节点，保持业务逻辑连贯性与完整性。

**典型场景示例：**

> 用户已完成数据清洗和特征提取，选中最后一个节点后输入："在此基础上增加模型评估节点，输出准确率和召回率。"

建模助手将自动在指定节点后衔接评估算子，并完成参数配置。

### 3.4 指令模板——预置模板与场景化指令，加速上手

指令模板降低智能建模的使用门槛，帮助用户快速上手。

**核心特性：**

- **快速上手**：内置多个指令模板，覆盖常见业务场景，帮助用户快速熟悉助手的使用方式。
- **灵活配置**：支持**全局化自定义配置**，管理员可按不同业务场景定制模板，适配组织内多样化需求。

### 3.5 知识库——让建模助手具备行业和业务"记忆"

知识库是智能建模的"大脑"，使 AI 具备企业级行业记忆，三大知识库协同运作：

| 知识库类型 | 作用说明 |
|------------|----------|
| **数据表知识库** | 让 AI 认识您的"积木"，精准推荐组织内数据表 |
| **算子知识库** | 让 AI 了解可用算子及其适用场景，推荐合适的处理组件 |
| **模型知识库** | 让 AI 学会您的"图纸"，将历史成功模型、业务文档作为知识，使规划方案更符合企业最佳实践 |

通过知识库，建模助手不再是通用 AI，而是真正**懂行业、懂数据、懂企业**的专属业务助手。

### 3.6 上下文引用——让建模助手"看懂"你的画布和意图

上下文引用将画布元素与对话紧密结合，实现高效、精准的智能化建模。支持三种引用方式：

| 引用方式 | 操作说明 |
|----------|----------|
| **拖动引用** | 将画布中的元素（如数据源、算子）直接拖入对话框 |
| **右键菜单引用** | 在算子上右键选择"引用"，快速将节点加入对话上下文 |
| **@ 快捷键引用** | 在对话框中输入 `@`，快速搜索并引用画布元素 |

通过上下文引用，用户可以精确指向特定节点或数据表，避免歧义，大幅提升 AI 理解的准确性。

### 3.7 快捷 AI 操作——让建模更顺手的实用技巧

在建模画布中，用户可一键调用 AI 能力，无需切换至对话界面：

| 功能 | 说明 |
|------|------|
| **算子智能重命名** | 依据算子的配置信息自动生成语义清晰的节点名称 |
| **智能注释** | 根据算子的配置信息自动生成节点注释，提升模型可读性 |
| **智能改写** | 在画布算子节点中即可快速调用 AI 改写，简化操作流程 |

## 4. 核心价值与变革

### 4.1 三大核心变革

智能建模为数据建模领域带来三个维度的深刻变革：

#### 交互变革：从"手动拖拽"到"自然语言驱动"

将建模人员从重复的配置工作中解放出来，提升建模效率，实现人机协同的全新交互模式。分析师以业务语言描述需求，AI 负责技术实现，双方各司其职、高效协作。

#### 流程变革：从"断点思考"到"连贯构建"

利用"模型续写"实现流程的自动化衔接，通过"模型改写"进行实时调优，确保业务分析师的思路不中断，加快模型迭代和优化速度。建模过程由碎片化操作变为连贯的思维流。

#### 智能变革：从"通用平台"到"专属业务助手"

私有知识库使 AI 具备企业级记忆，能够优先参考内部最佳实践，实现对建模意图的精准理解，真正成为懂行业、懂数据的专家助手。

### 4.2 核心总结

> **可视化建模 + AI 理解 + 行业知识融合 = 下一代数据生产力引擎**

智能建模的核心理念可以概括为四个"不是……而是……"：

| 理念 | 说明 |
|------|------|
| **不是取代而是增强** | AI 不是替代人类分析师，而是将其从重复劳动中解放，专注于更高阶的价值创造 |
| **不是黑箱而是透明协作** | 所有 AI 生成内容均可在画布查看、编辑、验证，确保人机协同的可控性与可信度 |
| **不是静态而是持续进化** | 系统随使用而不断学习与优化，形成企业专属的智能建模大脑 |
| **不是孤立功能而是生态连接器** | 与数据治理、BI 分析等系统深度融合，构成完整数据智能链条 |

## 5. 未来展望

智能建模的愿景是：**从想法到模型，只要一句话。**

未来将持续在以下四个方向深化演进：

### 5.1 融合更多算子

持续扩展 AI 可理解和调用的算子范围，覆盖更多数据处理、算法分析和业务逻辑场景，让自然语言建模的能力边界不断拓展。

### 5.2 指令模板自定义

支持自定义与共享模板，满足不同业务流程需求，快速实现建模指令标准化与复用，降低组织内的推广和培训成本。

### 5.3 私有知识库

支持上传私有知识，构建专属业务知识库，让 AI 更深入理解企业数据与场景逻辑，实现真正意义上的"企业专属智能建模大脑"。

### 5.4 模型优化建议

通过学习历史建模方式与结果，AI 主动识别改进空间并提出优化建议，助力模型持续进化，推动组织建模能力的系统性提升。
